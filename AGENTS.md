# Development and maintenance

- Read README.md, INSTALL.md and TASKS.json before changes.
- Never invent OS data or report unavailable probes as healthy.
- Preserve structured operation diagnostics across runner/helper/API/job storage. Never collapse an inner Git failure into only a runuser exit. Redact known credentials and secret patterns before bounding/persisting output; whitelist diagnostic fields, omit stdin/environment dumps, and keep reports authenticated. Diagnostics must not expand system permissions or execute suggested commands.
- Never run arbitrary shell strings or accept executable paths from HTTP.
- The web process is unprivileged. Root operations belong in helper/helper.py with a root-owned allowlist.
- Require authenticated sessions, same-origin checks and CSRF for every mutation. WebSockets must authenticate and revalidate sessions.
- Keep secrets out of API responses, logs and Git. Tests use temporary data and adapters only.
- Every helper/project test fixture must explicitly set state_dir inside its temporary directory, including static-project and invalid-input tests. Never probe the installed /var/lib/ubuntu-control-helper or relax its permissions to make non-root upgrade tests pass. Acceptance scripts must check installed module availability before importing helpers or creating test resources.
- Project files must remain within authorized roots; reject symlinks, secret paths and protected runtime data.
- Project folders can be created/opened through the authenticated site under the configured project_root. Do not reintroduce per-project manual helper.json approval. The helper persists these registrations in its private state directory; existing service allowlists remain separate.
- Never alter existing services/firewalls automatically. Protect management access and retain rollback state.
- GitHub App PEM path is pinned to /etc/ubuntu-control/github/app.pem. Only the capability-free ubuntu-github broker may read it. Never grant the web user key access or accept client key paths/content.
- GitHub installation credentials stay in broker/helper/runner memory, use read-only repository-scoped tokens for Git, and travel via anonymous stdin + temporary askpass socket. Never embed credentials in argv, environment values, remotes, Git config, logs or build processes. Validate installation repository membership before each lease.
- Keep Deploy Key projects compatible. Imports/pulls require authenticated CSRF-protected actions and resource locks; configuration/disconnection require password/TOTP reauthentication.
- Upgrade existing servers with scripts/upgrade.sh, not install.sh. Build root-owned source in an isolated staging tree as the service user, back up configuration/SQLite/state, preserve existing service customizations and retain previous code for rollback.
- Run npm test, npm run build, and npm run check:helper after relevant changes. Ubuntu integration must be labeled unverified until tested on Ubuntu.
- Managed lifecycle authority is helper/project_lifecycle.py; SQLite lifecycle_json/update_state are mirrors and scheduling metadata. Preserve additive migrations, manual defaults, root transaction recovery and per-project/build locks. Never mark a deployment healthy before its local HTTP check or 20-second process stability check, including rollback recovery.
- Generated uc-project-<hash>.service units live in /run/systemd/system and are regenerated from the private registry on boot. Node uses DynamicUser, read-only source, private StateDirectory and LoadCredential with the root-owned runtime_launcher.py. Do not broaden the helper's /etc or web permissions to install units.
- systemd scalar WorkingDirectory paths must not be JSON/shell quoted; list directives have different parsing rules. Escape literal percent specifiers and validate generated units with the Linux systemd parser. Acceptance failures must preserve redacted primary diagnostics even when cleanup fails; isolated acceptance registries require their own scoped recovery, not a main-helper restart.
- BindPaths must quote source and destination separately, leaving the separating colon outside quotes. A quoted whole pair parses as one source filename and can pass syntax verification; Linux parser tests must inspect the parsed BindPaths source/destination in the debug unit dump, not only verify's exit status.
- Project env API returns key names/public-build flags only. PATCH blanks preserve values, deletion is explicit, changes require password/TOTP. Atomically persist root-only values outside releases; only explicit publicBuild keys may enter builds. Redact runtime secrets before journal emission and before bounded log/report storage.
- Docker is the dedicated ubuntu-docker rootless engine; never use the rootful socket for managed projects or mount engine sockets into containers. scripts/setup-rootless-docker.sh is an explicit operator action, not an upgrade side effect. Preserve allowlisted legacy services and shared-resource checks.
- Console subscriptions must revalidate sessions, share one source per project, stop on last unsubscribe, bound buffers, signal gaps and resume cursors. No interactive terminal input. Automatic updates check SHA/ETag every 60 seconds, max two network checks and one build; unchanged/failed SHAs must not loop through builds. Pull-only remains separate from deploy.
- Archive preserves code, env and persistent data indefinitely. Restore is stopped/manual; purge is archive-only, reauthenticated, scoped and resumable. Preserve audit/jobs. Runtime transaction journals are private and must recover before new mutations or upgrades; do not simply delete a pending journal.
- Run scripts/acceptance-runtime.py on upgraded Ubuntu for real DynamicUser/systemd and optionally --docker for rootless integration. It creates isolated test projects; never run it against user project paths or claim its simulated adapters prove real reboot/GitHub delivery.
- Builds use fixed uc-build-<hash>-source/image transient units with --pipe/--wait, unprivileged users and KillMode=control-group. Keep Git tokens on anonymous stdin. Recovery must stop orphaned build units before selecting current; do not add CAP_KILL or arbitrary transient-unit actions. Keep firewall mutation reservation and project/service locks mutually exclusive while leaving log reads independent.
- Queued project actions/imports must not navigate to Jobs automatically. Keep the current page and show acknowledgment. Project links use real server interface addresses or explicit HTTP(S) URLs, never guessed public addresses; reject management-host URLs (including other ports) to avoid cookie leakage. Remote IPv4 listening requires explicit runtime selection; default remains localhost and direct runtime listening never changes firewall rules. Managed publication changes only explicitly authorized, app-owned rules.
- New runtime configuration defaults to dependencyInstall=install (npm install even with a lockfile). Preserve existing locked (npm ci) and allow-install (ci if locked, install otherwise) policies. Install only inside releases; never auto-switch package managers, update source lockfiles, push, or expose runtime secrets to builds. Console empty states must distinguish loading, idle/stopped services and deployment failures; retain redacted per-project job diagnostics and bounded, visibility-scoped HTTP fallback when WebSocket is unavailable.
- ENV import is a bounded UTF-8 merge through the helper, with password/TOTP, reserved-name checks, no expansion/execution and no value-bearing preview/errors. Import KEY= explicitly clears a value; manual PATCH blanks still preserve it. Imported keys become runtime-private. Never persist uploaded raw text or echo values to API/Audit.
- Job progress uses framed runner stderr and helper events, redacted before bounded SQLite storage. Preserve final diagnostic frames and callback compatibility. No screenshots in debugging or UI tests; use DOM assertions. Run focused UI coverage, not unrelated suites repeatedly.
- Publication authority is helper/publication.py. Only explicit authenticated/CSRF/reauthenticated requests may publish. Keep Node on loopback and Nginx on the configured public interface, with fixed proxy templates, validated ports and root-only ACME state. Never accept Nginx text, command strings, certificate paths or arbitrary upstreams from clients. Retain per-project/network/firewall locking, transaction backups and startup recovery; never take ownership of unrelated UFW rules or Nginx listeners. No cloud firewall changes are inferred.
- scripts/setup-publication.sh is an explicit Ubuntu operator preparation, separate from upgrade. It installs isolated Certbot >=5.4, scoped helper write paths and a renewal timer. Upgrade must preserve publication state, keys, proxy files and pending transaction checks; it must not publish anything. Management public origins are an exact allowlist preserving the original Tailscale origin, and project URLs must reject all management hostnames to protect cookies.
